# Design Tokens

Design tokens are the visual design atoms of the design system — named entities that store visual design attributes.

## Why Tokens?

Tokens provide:

- **Consistency** - Single source of truth for design values
- **Maintainability** - Update once, change everywhere
- **Theming** - Easy theme switching
- **Scale** - Systematic design at any size

## Token Categories

### Color Tokens

Semantic color tokens organized by purpose:

#### Text Colors
```css
--color-text-primary      /* Main text */
--color-text-secondary    /* Supporting text */
--color-text-tertiary     /* Subtle text */
--color-text-disabled     /* Disabled text */
--color-text-inverse      /* Text on dark backgrounds */
--color-text-link         /* Hyperlinks */
--color-text-success      /* Success messages */
--color-text-error        /* Error messages */
--color-text-warning      /* Warning messages */
```

#### Background Colors
```css
--color-background-primary    /* Main surface */
--color-background-secondary  /* Secondary surface */
--color-background-tertiary   /* Tertiary surface */
--color-background-hover      /* Hover state */
--color-background-disabled   /* Disabled state */
```

#### Brand Colors
```css
--color-primary           /* Primary brand */
--color-primary-hover     /* Primary hover */
--color-primary-active    /* Primary active/pressed */
--color-secondary         /* Secondary brand */
--color-secondary-hover   /* Secondary hover */
--color-secondary-active  /* Secondary active */
```

#### State Colors
```css
--color-success           /* Success states */
--color-error             /* Error states */
--color-warning           /* Warning states */
--color-info              /* Info states */
```

## Using Tokens

### In React Components

Import and use tokens with TypeScript support:

```tsx
import { themeVars } from '@django-core/design-system';

const MyComponent = () => (
  <div style={{
    padding: themeVars.spacing[4],
    backgroundColor: themeVars.color.background.primary,
    borderRadius: themeVars.radius.md,
  }}>
    Content
  </div>
);
```

### In CSS

Reference tokens via CSS custom properties:

```css
.my-element {
  padding: var(--spacing-4);
  color: var(--color-text-primary);
  background: var(--color-background-primary);
  border-radius: var(--radius-md);
  box-shadow: var(--shadow-md);
}
```

### In Django Templates (B14)

Import the tokens CSS file:

```html
<link rel="stylesheet" href="{% static 'design-system/tokens.css' %}">

<div class="my-card" style="
  padding: var(--spacing-4);
  background: var(--color-background-secondary);
  border-radius: var(--radius-md);
">
  Content
</div>
```

## Token Architecture

### Tier System

Tokens are organized in two tiers:

1. **Base tokens** - Raw values (colors, sizes)
2. **Semantic tokens** - Purpose-based (text-primary, background-hover)

This allows themes to remap base tokens without changing semantic meaning:

```css
/* Light theme */
--color-text-primary: var(--color-gray-900);

/* Dark theme */
--color-text-primary: var(--color-gray-50);
```

### Theme Switching

All semantic tokens automatically update when themes switch:

```tsx
<ThemeProvider theme="dark">
  {/* All components use dark theme tokens */}
</ThemeProvider>
```

## Best Practices

### Do's ✅

- Use semantic tokens (`text-primary` instead of `gray-900`)
- Follow the spacing scale consistently
- Use motion tokens for animations
- Respect z-index layers

### Don'ts ❌

- Don't hard-code pixel values
- Don't skip spacing scale steps
- Don't create custom z-index values
- Don't override base tokens directly

## Extending Tokens

For project-specific needs, extend semantic tokens:

```css
:root {
  --color-accent: #ff00ff;
  --spacing-custom: calc(var(--spacing-4) * 1.5);
}
```

But prefer using existing tokens when possible.
