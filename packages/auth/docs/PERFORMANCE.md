# Performance Testing Guide

This document outlines the performance testing strategy for `@django-core/auth-ui`.

## Bundle Size

### Targets

- **Maximum**: 15 KB gzipped (ESM format)
- **Current**: 6.28 KB gzipped (ESM), 5.26 KB gzipped (CJS)
- **Budget Usage**: 42% (8.72 KB headroom)

### Monitoring

#### Local Development

**View Bundle Analysis**:
```bash
cd packages/auth
pnpm analyze
```

This opens `dist/stats.html` with an interactive treemap showing:
- Module sizes (raw, gzipped, brotli)
- Dependency relationships
- Largest contributors to bundle size

**Check Bundle Size**:
```bash
cd packages/auth
pnpm build
```

Build output shows gzipped sizes for both ESM and CJS formats.

#### CI/CD Pipeline

The `.github/workflows/auth-ui.yml` workflow includes automated bundle size checks:

1. **Build Step**: Builds production bundle
2. **Size Check**: Runs `size-limit` to verify bundle ≤15KB gzipped
3. **Reporting**:
   - Fails PR if bundle exceeds limit
   - Uploads `stats.html` as artifact for review
   - Posts bundle size summary to PR

### Configuration

**`package.json`**:
```json
{
  "sideEffects": false,
  "size-limit": [
    {
      "path": "dist/index.js",
      "limit": "15 KB",
      "gzip": true,
      "running": false
    }
  ]
}
```

**`vite.config.ts`**:
- `external`: Peer dependencies (React, design-system) not bundled
- `minify: 'esbuild'`: Fast minification
- `rollup-plugin-visualizer`: Bundle analysis

### Optimization Checklist

- ✅ **Peer Dependencies Externalized**: React, React-DOM, @django-core/design-system
- ✅ **Tree-Shaking Enabled**: `sideEffects: false` in package.json
- ✅ **Minification**: esbuild with es2020 target
- ✅ **Source Maps**: Separate `.map` files (not in bundle)
- ✅ **No Code Splitting**: Bundle already optimal (<15KB)

## Future Improvements

### Potential Optimizations

1. **Lazy Loading**: If bundle grows >12KB, consider lazy loading:
   - Password reset flows (used less frequently)
   - Profile management (accessed after sign-in)

2. **Module Federation**: For multi-page apps:
   - Share React/design-system across pages
   - Load only needed components per route

3. **Compression**: Brotli compression (beyond gzip):
   - Current: 6.28KB gzipped
   - Potential: ~5.5KB brotli (12% smaller)

### Monitoring Strategy

1. **Bundle Size Tracking**:
   - Size-limit in CI (prevents regressions)
   - Bundle stats artifact for PR reviews
   - Automated alerts if approaching limit

2. **Runtime Performance** (when implemented):
   - Lighthouse CI on example app
   - Real User Monitoring (RUM) in production
   - Performance marks for key interactions
