## 🚀 Quick Start: Integrating a New Module

When building a new module (e.g., B52 Match Events, B54 Formation Models), follow this checklist:

### 1. Understand the Hierarchy
```
Organisation (KNVB, DFB, etc.)
└── Project (Club: "AFC Ajax")
    └── Project (Team: "Ajax 1")
        └── Period (Season: "2024/2025")
            └── Period (Competition: "Eredivisie")
                └── Match, MatchTemplate, Roster, etc.
```

**See**: [glossary.md](glossary.md) for what each concept means.

### 2. Check FK Dependencies
Before adding models:
1. Open [schema/tables.md](schema/tables.md)
2. Find your FK targets (e.g., `project_id`, `organisation_id`)
3. Verify those tables have data: [state/counts.md](state/counts.md)

### 3. Write Idempotent Seeds
All seeds MUST be production-safe:
```python
# ✅ CORRECT - Idempotent
obj, created = MyModel.objects.update_or_create(
    natural_key="unique-identifier",
    defaults={"field": "value"}
)

# ❌ WRONG - Creates duplicates
MyModel.objects.create(natural_key="unique-identifier", field="value")
```

**See**: [seeding/guide.md](seeding/guide.md) for full patterns.

### 4. Test Against Real Data
```bash
# Set Railway DATABASE_URL
$env:DATABASE_URL="postgresql://postgres:<PASSWORD>@switchback.proxy.rlwy.net:17304/railway"

# Run your seed
python scripts/seed_my_module.py

# Verify
python manage.py shell
>>> from myapp.models import MyModel
>>> MyModel.objects.count()
```

## ⚠️ Production Safety Rules

1. **NEVER DROP TABLES** - Use migrations with `update_or_create`
2. **NEVER DELETE DATA** - Soft-delete with `is_active=False` if needed
3. **ALWAYS USE NATURAL KEYS** - For idempotent seeds (e.g., `slug`, `external_id`)
4. **TEST LOCALLY FIRST** - Run seeds against local SQLite before Railway
