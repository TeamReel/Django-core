## Work Package WP02: PromptService Core + Cache Infrastructure (Priority: P0)

**Goal**: Build the `PromptService` module with cached template lookups, prompt resolution with variable substitution, and signal-based cache invalidation.
**Independent Test**: `pytest tests/generative/test_prompt_service.py` — all service tests pass (get_template, resolve_prompt, cache invalidation).
**Prompt**: `tasks/WP02-prompt-service-core.md`
**Requirement Refs**: FR-001, FR-002, FR-003, FR-005, NFR-001, NFR-002

### Included Subtasks
- [ ] T001 Create `src/generative/services/prompt_service.py` module skeleton with `GenerationTemplateNotFound` exception and migrate PARAM_RESOLVERS, ROLE_EQUIPMENT, OUTFIT_STYLE_DETAILS constants from legacy `teamreel_prompts.py`
- [ ] T002 Write unit tests for `get_template()` and `get_active_templates()` — cache hit/miss, not-found exception, org-scoping
- [ ] T003 Implement `get_template()` and `get_active_templates()` with `@cache_result` decorator (TTL 300s, tag-based invalidation via `prompt_templates` tag)
- [ ] T004 Write unit tests for `resolve_prompt()` — basic `{placeholder}` substitution, PARAM_RESOLVERS lookup, home-kit override, user_instruction append, edge cases (missing param, empty prompt)
- [ ] T005 Implement `resolve_prompt()` — template variable substitution using PARAM_RESOLVERS, special cases (home-kit override, user_instruction, guest player)
- [ ] T006 Create `src/generative/signals.py` with `post_save` cache invalidation for GenerationTemplate, update `src/generative/apps.py:ready()` to register signals, write signal invalidation tests

### Implementation Notes
- Follow TEST_FIRST: write tests (T002) before implementation (T003), tests (T004) before implementation (T005).
- Use existing `@cache_result` decorator from `src/core/cache/decorators.py` — established project pattern.
- PARAM_RESOLVERS are migrated as module-level constants (not DB) — they are static domain knowledge shared across all templates.
- `resolve_prompt()` migrates logic from legacy `teamreel_prompts.resolve_prompt()` in `archive/legacy-root-cleanup/scripts/teamreel_prompts.py`.

### Parallel Opportunities
- T002 and T004 (test writing) can be written in parallel as they test different functions.
- T001 (constants migration) is independent preparatory work.

### Dependencies
- None — builds on existing GenerationTemplate model (WP01 on main).

### Risks & Mitigations
- **PARAM_RESOLVERS fidelity**: Ensure all ~80 value→text mappings are correctly migrated from legacy file. Mitigation: cross-reference with `archive/legacy-root-cleanup/scripts/teamreel_prompts.py`.
- **Cache decorator compatibility**: Verify `@cache_result` works with Django model instances. Mitigation: test cache serialization in T002.

## Work Package WP03: Pipeline Refactor — Replace importlib Call Sites (Priority: P0)

**Goal**: Replace all 4 importlib call sites in `views_generate.py` and `asset_pipeline.py` with PromptService database lookups. Zero importlib references remain in production code.
**Independent Test**: `pytest tests/generative/test_prompt_pipeline_integration.py` — pipeline uses DB templates for image and video generation. Plus full regression: `pytest tests/generative/` passes with zero failures.
**Prompt**: `tasks/WP03-pipeline-refactor-importlib.md`
**Requirement Refs**: FR-004, FR-006, NFR-003, NFR-004, C-005

### Included Subtasks
- [ ] T007 Write integration tests for pipeline using PromptService — image generation uses DB template, video generation uses DB template, legacy FBV returns DB templates
- [ ] T008 Replace importlib in `src/generative/views_generate.py:list_asset_templates_view()` (L878-895) with DB query via `get_active_templates()` — maintain response format for backward compat (C-005)
- [ ] T009 Replace importlib in `src/generative/services/asset_pipeline.py:_get_template_output_type()` (L55-85) and `_load_prompts_module()` (L375-390) with PromptService calls
- [ ] T010 Replace importlib in `src/generative/services/asset_pipeline.py:generate_asset()` (L129-165) with PromptService — preprocessing config from DB, resolve_prompt from service, input requirements from `input_schema`
- [ ] T011 Remove all unused importlib imports, verify no importlib references remain in `src/generative/`, run full regression test suite

### Implementation Notes
- **Call site A** (`list_asset_templates_view`): Replace with `get_active_templates()` → format response to match existing JSON structure (`id`, `name`, `category`, `description`, `input_requirements`, `parameters`). C-005 mandates backward compat.
- **Call site B** (`_get_template_output_type`): Simple replacement — `get_template(slug).pipeline_config.get("output_type", "image")`.
- **Call site C** (`generate_asset`): Most complex — must replace preprocessing config lookup, resolve_prompt call, input_requirements check, and template config for Gemini API.
- **Call site D** (`_load_prompts_module`): Used by video generation — replace with `get_template()` + `resolve_prompt()`.
- All 4 sites currently fail silently (file at archive path, not project root).

### Parallel Opportunities
- T008 (views_generate.py) and T009+T010 (asset_pipeline.py) touch different files and can be done in parallel.

### Dependencies
- Depends on WP02 — requires PromptService functions.

### Risks & Mitigations
- **Response format regression (C-005)**: The legacy FBV format differs from the DRF ModelViewSet format. Mitigation: T007 tests verify exact response structure.
- **generate_asset() complexity**: This function has many touchpoints. Mitigation: T010 has detailed step-by-step guidance, integration test covers full flow.

## Work Package WP04: Serializer Validation + Regression (Priority: P1)

**Goal**: Add structural validation for `parameters_schema` and `preprocessing_config` to the serializer. Verify all FRs/NFRs are satisfied end-to-end.
**Independent Test**: `pytest tests/generative/test_prompt_serializer_validation.py` — all validation tests pass. Full suite: `pytest` passes with zero regressions.
**Prompt**: `tasks/WP04-serializer-validation-regression.md`
**Requirement Refs**: FR-007, FR-008, FR-009, NFR-003

### Included Subtasks
- [ ] T012 Write tests for `validate_parameters_schema()` — valid schema passes, missing `label` fails, missing `type` fails, non-dict value fails, empty dict passes, nested options validated
- [ ] T013 Add `validate_parameters_schema()` to `GenerationTemplateSerializer` in `src/generative/serializers.py` — validate each value has `label` (str) and `type` (str)
- [ ] T014 Write tests for `validate_preprocessing_config()` — valid config passes, non-string value fails, non-dict fails, empty dict passes
- [ ] T015 Add `validate_preprocessing_config()` to `GenerationTemplateSerializer` in `src/generative/serializers.py` — validate each value is a string
- [ ] T016 Full regression verification: run `pytest`, `python manage.py check`, `ruff check src/` — verify zero failures, verify API returns `parameters_schema` + `preprocessing_config` + description (FR-006), verify admin displays editable fields (FR-007)

### Implementation Notes
- Follow TEST_FIRST: write validation tests (T012) before implementation (T013), tests (T014) before implementation (T015).
- Model `clean()` already validates `parameters_schema` (each value needs `label` + `type`). Serializer validation gives better API-level error messages.
- `preprocessing_config` validation: each value must be a string (preprocessor function name).

### Parallel Opportunities
- T012+T013 (parameters_schema) and T014+T015 (preprocessing_config) are completely independent and can be done in parallel.

### Dependencies
- None — serializer validation is independent, adds methods to existing `GenerationTemplateSerializer`.

### Risks & Mitigations
- **Validation strictness**: Too strict validation could reject existing seed data. Mitigation: T012/T014 tests verify that existing seed templates pass validation.
