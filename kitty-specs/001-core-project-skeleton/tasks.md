# Work Packages: Core Project Skeleton

**Inputs**: Design documents from `kitty-specs/001-core-project-skeleton/`
**Prerequisites**: plan.md (required), spec.md (user stories), research.md, quickstart.md, contracts/health.yaml

**Tests**: Smoke tests included to validate skeleton configuration (no domain logic tests).

**Organization**: Fine-grained subtasks (`Txxx`) roll up into work packages (`WPxx`). Each work package must be independently deliverable and testable.

**Prompt Files**: Each work package references a matching prompt file in `tasks/planned/` generated by `/spec-kitty.tasks`. Treat this file as the high-level checklist; keep deep implementation detail inside the prompt files.

**Constitutional Compliance**: All tasks align with Django Core-App Constitution principles. Reference `.kittify/memory/constitution.md` for governance rules.

## Subtask Format: `[Txxx] [P?] Description`
- **[P]** indicates the subtask can proceed in parallel (different files/components).
- Include precise file paths or modules.

## Path Conventions
- **Django project**: `src/[package_name]/`, `tests/`
- Adjust paths to match the implementation plan.

## Task Categories (Constitution-Aligned)

Tasks are organized to reflect constitutional principles:

- **Setup & Infrastructure (P0)**: Project structure, dependency management
- **Settings Configuration (P0)**: Environment-based settings, secure defaults
- **Testing Infrastructure (P0)**: pytest-django setup, smoke tests, coverage
- **Security & Privacy (P0)**: Environment variables, .gitignore, secure defaults
- **Observability (P0)**: Structured logging, health checks, metrics placeholders
- **Code Quality (P0)**: Black, Ruff, mypy, pre-commit hooks
- **Documentation (P1)**: README, extension guides, ADRs
- **Validation (P2)**: End-to-end verification, success criteria validation

## Work Package WP01: Project Structure & Dependencies (Priority: P0)

**Goal**: Establish Django project skeleton with src/ layout and pinned dependencies per Constitution Principles II, III, VIII.
**Independent Test**: Project directory structure exists, dependencies install without errors, Django project initialized.
**Prompt**: `tasks/planned/WP01-project-structure-and-dependencies.md`

### Included Subtasks
- [ ] T001 Create src/ directory structure with config/, core_apps/, common/ subdirectories
- [ ] T002 Initialize Django project using `django-admin startproject config src/`
- [ ] T003 Create requirements files structure (requirements/base.txt, local.txt, production.txt)
- [ ] T004 [P] Create pyproject.toml with project metadata and Python 3.12+ requirement
- [ ] T005 [P] Pin core dependencies in requirements/base.txt (Django 5.1, DRF, django-environ)
- [ ] T006 [P] Pin development dependencies in requirements/local.txt (pytest, pytest-django, Black, Ruff, mypy, coverage, pre-commit)
- [ ] T007 [P] Pin production dependencies in requirements/production.txt (python-json-logger, psycopg2-binary)

### Constitutional Alignment
- Principle II (Architecture): src/ layout with clear separation
- Principle III (Code Quality): Python 3.12+ baseline, curated dependencies
- Principle VIII (Developer Experience): Easy setup foundation

### Implementation Notes
- Use `django-admin startproject` to generate initial Django structure
- Organize requirements by environment (base shared, local dev-only, production prod-only)
- Pin all dependencies to specific versions (no loose ranges)
- pyproject.toml will hold tool configurations (Black, Ruff, mypy, pytest)

### Parallel Opportunities
- Requirements files (T005-T007) can be created in parallel
- pyproject.toml (T004) independent of requirements files initially

### Dependencies
- None (starting package).

### Risks & Mitigations
- Dependency conflicts → Use compatible version combinations from research.md
- Django project structure conflicts → Customize startproject output as needed

## Work Package WP02: Settings & Configuration (Priority: P0)

**Goal**: Implement environment-based Django settings with secure defaults per Constitution Principles V, VI.
**Independent Test**: Settings modules load without errors, environment detection works, secure defaults validated.
**Prompt**: `tasks/planned/WP02-settings-and-configuration.md`

### Included Subtasks
- [ ] T008 Create src/config/settings/ package structure with __init__.py
- [ ] T009 Implement src/config/settings/base.py with secure defaults (CSRF, cookies, ALLOWED_HOSTS, SECRET_KEY via env)
- [ ] T010 Configure Django REST Framework in base settings (pagination, auth, renderers)
- [ ] T011 Configure structured logging in base settings (JSON formatter, console handler)
- [ ] T012 Implement src/config/settings/local.py (DEBUG=True, SQLite, human-readable logging, browsable API)
- [ ] T013 Implement src/config/settings/staging.py (secure defaults, PostgreSQL support)
- [ ] T014 Implement src/config/settings/production.py (DEBUG=False, HTTPS, secure cookies, JSON logging)
- [ ] T015 Update src/config/settings/__init__.py to auto-detect environment or use DJANGO_SETTINGS_MODULE

### Constitutional Alignment
- Principle V (Security): Secure defaults, CSRF enabled, no secrets in code
- Principle VI (Performance & Reliability): Structured logging, system check configuration
- Principle VII (API Design): DRF configuration with pagination

### Implementation Notes
- base.py contains 80% of settings (shared across environments)
- Each environment file imports from base: `from .base import *`
- Use django-environ for environment variable management
- Logging configuration: JSON in production, human-readable in local
- DRF config: PageNumberPagination, SessionAuthentication, JSONRenderer

### Parallel Opportunities
- Environment-specific files (T012-T014) can develop in parallel after base.py complete
- DRF config (T010) and logging config (T011) independent within base.py

### Dependencies
- Depends on WP01 (project structure and dependencies must exist).

### Risks & Mitigations
- Missing environment variables → Fail fast with clear error messages
- Settings import errors → Use `from .base import *` pattern carefully, avoid circular imports
- SECRET_KEY exposure → Use django-environ, document in .env.example, never commit secrets

## Work Package WP03: Health Check & Observability (Priority: P0)

**Goal**: Implement health check endpoint and observability placeholders per Constitution Principle VI.
**Independent Test**: GET /health/ returns 200 OK with JSON response, metrics middleware exists.
**Prompt**: `tasks/planned/WP03-health-check-and-observability.md`

### Included Subtasks
- [ ] T016 Create src/common/__init__.py package
- [ ] T017 Implement src/common/health.py with health check view function
- [ ] T018 [P] Create placeholder src/common/middleware.py for metrics (no-op implementation)
- [ ] T019 Add /health/ URL route in src/config/urls.py

### Constitutional Alignment
- Principle VI (Performance & Reliability): Health checks mandatory, metrics hooks required

### Implementation Notes
- Health check view returns JSON: `{"status": "healthy", "timestamp": "ISO8601"}`
- Middleware placeholder is a no-op class ready for future instrumentation
- URL route uses Django's path() function, not DRF (simpler for non-API endpoint)
- Health check should respond quickly (< 100ms success criterion)

### Parallel Opportunities
- Health check view (T017) and middleware (T018) are independent

### Dependencies
- Depends on WP02 (settings must be configured for URLs to work).

### Risks & Mitigations
- Health check too slow → Keep implementation simple (no database checks in skeleton)
- URL conflicts → Use /health/ with trailing slash (Django convention)

## Work Package WP04: Testing Infrastructure (Priority: P0)

**Goal**: Set up pytest-django testing framework with smoke tests per Constitution Principle IV.
**Independent Test**: `pytest` runs successfully, coverage report generated, all smoke tests pass.
**Prompt**: `tasks/planned/WP04-testing-infrastructure.md`

### Included Subtasks
- [ ] T020 Create tests/ directory structure with __init__.py
- [ ] T021 Configure pytest in pyproject.toml (DJANGO_SETTINGS_MODULE, coverage, reuse-db)
- [ ] T022 Create tests/conftest.py with pytest-django fixtures
- [ ] T023 Implement tests/test_health.py (health check endpoint tests)
- [ ] T024 Implement tests/test_settings.py (settings validation tests)
- [ ] T025 Configure coverage in pyproject.toml (src/ coverage, HTML reports, minimum threshold)

### Constitutional Alignment
- Principle IV (Testing): pytest + pytest-django, deterministic tests, coverage thresholds

### Implementation Notes
- pytest configuration in pyproject.toml: `DJANGO_SETTINGS_MODULE = "config.settings.local"`
- Use pytest-django's `client` fixture for HTTP tests
- Use `--reuse-db` to speed up test runs
- Coverage minimum threshold: 80% for initial baseline (can increase over time)
- Tests must be fast (< 5 seconds total for skeleton)

### Parallel Opportunities
- Test files (T023-T024) can be written in parallel after conftest.py exists

### Dependencies
- Depends on WP02 (settings), WP03 (health check endpoint).

### Risks & Mitigations
- Test failures on fresh clone → Ensure all tests are deterministic, no external dependencies
- Slow tests → Use pytest-django's --reuse-db, keep tests simple
- Coverage too low → Add more smoke tests to cover settings modules

## Work Package WP05: Code Quality Tooling (Priority: P0)

**Goal**: Configure Black, Ruff, mypy, and pre-commit hooks per Constitution Principles III, VIII, X.
**Independent Test**: Black, Ruff, mypy run without errors on skeleton code, pre-commit hooks install successfully.
**Prompt**: `tasks/planned/WP05-code-quality-tooling.md`

### Included Subtasks
- [ ] T026 Configure Black in pyproject.toml (line-length 100, Python 3.12)
- [ ] T027 Configure Ruff in pyproject.toml (E, W, F, I, N, S, B rules, line-length 100)
- [ ] T028 Configure mypy in pyproject.toml (strict mode, Python 3.12, django-stubs)
- [ ] T029 Create .pre-commit-config.yaml with Black, Ruff, mypy, trailing-whitespace hooks
- [ ] T030 Create .editorconfig for consistent editor settings

### Constitutional Alignment
- Principle III (Code Quality): Black, Ruff, mypy mandatory
- Principle VIII (Developer Experience): Pre-commit hooks match CI
- Principle X (CI/CD): Quality gates preparation

### Implementation Notes
- Black: Uncompromising formatter, zero configuration beyond line-length
- Ruff: Fast linter covering pycodestyle, pyflakes, isort, bandit, bugbear
- mypy: Strict mode for src/config/ only (gradual typing)
- pre-commit: Runs Black → Ruff → mypy in sequence
- .editorconfig: indent_style=space, indent_size=4, trim_trailing_whitespace

### Parallel Opportunities
- Tool configurations (T026-T028) can be written in parallel in pyproject.toml
- .pre-commit-config.yaml (T029) and .editorconfig (T030) are independent

### Dependencies
- Depends on WP01 (pyproject.toml must exist).

### Risks & Mitigations
- Tool version conflicts → Pin versions in .pre-commit-config.yaml and requirements
- mypy type errors in Django code → Install django-stubs and djangorestframework-stubs
- Pre-commit too slow → Acceptable for first run (installs tools), faster on subsequent runs

**Prompt**: `tasks/planned/WP08-validation-and-success-criteria.md`

- [ ] T046 Run mypy on src/config/ and fix type errors

- [ ] T048 Install pre-commit hooks and verify they run correctly
- [ ] T049 Verify setup time meets < 10 minute success criterion (fresh clone test)
- [ ] T050 Verify health check endpoint responds in < 100ms

### Constitutional Alignment
- Principle III (Code Quality): All tools run clean
- Principle IV (Testing): All tests pass
- Principle V (Security): Deployment check passes
- Principle VIII (Developer Experience): Setup time meets goal

### Implementation Notes
- Run all quality checks in sequence
- Fix any issues discovered during validation
- Time a fresh clone setup to verify SC-001 (< 10 minutes)
- Measure health check response time to verify SC-004 (< 100ms)

- Individual tool checks (T044-T047) can run in parallel
- Setup time test (T049) and health check timing (T050) are independent

- Depends on all previous work packages (validates complete skeleton).

### Risks & Mitigations
