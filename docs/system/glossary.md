# GLOSSARY.md

## Purpose

This document defines key terms used in the Django Core-App project.
It helps humans and AI agents to use a shared vocabulary.

---

## Core Terms

- **Core-App**
  The Django Core-App platform itself: **68 modules** across **16 development phases**, providing an 80/20 platform foundation for modern web applications.

- **80/20 Principle**
  The Core-App provides 80% reusable infrastructure (multi-tenancy, security, content, real-time, workflows, data governance, optional AI/ML), while downstream products add only 20% domain-specific logic.

- **Downstream product**
  Any application that uses the Core-App as a starting point or shared core and adds domain-specific logic (e-commerce, CRM, content platform, etc.).

- **Spec-Driven Development (SDD)**
  A workflow where every feature is explicitly specified, planned and broken into tasks before implementation.

- **Spec Kitty**
  The toolkit and command set used to manage specs, plans, tasks and reviews (`/spec-kitty.*` commands).

- **Constitution**
  The global engineering rules and quality standards for the project, captured in `ENGINEERING_CONSTITUTION.md`.

- **Constitutional Enforcement Engine (B02)**
  The rule engine that checks repositories and workflows for compliance with the constitution and SDD process. Enforced at P01 Constitutional Gate (Fase 14).

- **Module Categories**
  - **B** (Backend): B01–B28 (28 modules, Fase 1-5, 8-9)
    - Core: B01-B21 (foundation, identity, APIs, tasks, observability)
    - Extensions: B22-B28 (files, real-time, search, cache, payments, workflows, documents)
  - **F** (Frontend): F01–F14 (14 modules, Fase 6-7, 8-10)
    - Core: F01-F07, F09 (design system, auth, context, notifications, resources, templates, theme, integration guides)
    - Extensions: F08, F10-F14 (data viz, demo + dev dashboard, ops console, billing UI, rich text, admin panel)
  - **P** (Platform Gates): P01–P05 (5 modules, Fase 14) — Lightweight quality checks
  - **D** (Data/ML): D01–D16 (16 modules, Fase 11-13) — Optional power-up
  - **I** (Integration): I01–I02 (2 modules, Fase 15) — Lightweight
  - **O** (Operations): O01 (1 module, Fase 16) — Lightweight

## Identity and Multi-Tenancy

- **User**
  An authenticated identity in the system, represented by the core accounts module (B05).

- **Organisation**
  A company, team, club or unit that owns resources and has members (B06).

- **Project / Workspace**
  A contextual container within an organisation for resources and workflows (B07).

- **Hierarchical Access Control**
  Permission model that spans global, organisation and project scopes (B08).

---

## Configuration and Usage

- **Settings & Feature Flags**
  Configuration and toggles that control behaviour at global/org/project scope (B10).

- **Transaction / Credit**
  A generic record representing usage, balance changes or billable events (B11).

- **Preference**
  User/organisation-specific choice such as language, locale or timezone (B12).

---

## Interfaces and Communication

- **API Baseline (B13)**
  The standardised DRF-based interface for exposing Core-App entities.

- **Web-UI Baseline (B14)**
  Minimal server-rendered HTML templates and navigation for core entities.

- **Notification**
  A message generated by the system and delivered via one or more channels (B16/B17).

---

## Frontend

- **Design System (F01)**
  A collection of design tokens, components and guidelines used across UIs.

- **Context Switcher (F03)**
  UI element that allows switching between organisations and projects.

- **App Shell / Layouts (F06)**
  The main layout structure: navigation, content, headers, footers, etc.

- **Resource Display & Alerts (F05)**
  UI patterns for showing usage, credits, limits and alerts.

---

## Workflow and Tooling

- **Work Package (WPxx)**
  A coherent block of work within a feature (e.g. `WP01-model-and-migrations`).

- **Task (Txxx)**
  A small, testable item within a work package.

- **Vibecoding**
  Interactive, iterative coding with AI agents (ChatGPT, Copilot) where context and prompts are continuously refined.

---

## Modern Web Capabilities (Fase 8-10)

- **Design-to-Code Workflow (F09)**
  Visily.ai-style pipeline where AI-generated wireframes/designs are converted to production components using F01 design system tokens.

- **File & Media Management (B22)**
  Upload, storage, processing and delivery of files/images via storage adapters (S3, Azure, local).

- **Cache Layer (B25)**
  Redis-backed caching with decorator patterns and invalidation strategies.

- **Real-time Infrastructure (B23)**
  Django Channels-based WebSocket support for live updates, activity streams and collaborative features.

- **Full-text Search (B24)**
  PostgreSQL full-text search (pg_trgm, GIN indexes) with optional Elasticsearch adapter.

- **Workflow Engine (B27)**
  State machine patterns for approval flows, order status transitions and business processes.

- **Payment Gateway Adapters (B26)**
  Multi-gateway payment integration (Stripe first, PayPal/Braintree adapters) with webhook handling.

- **Document Generation (B28)**
  PDF/Excel report generation via templates (WeasyPrint for PDFs, openpyxl for Excel).

- **Rich Text Editor (F13)**
  WYSIWYG editor component (TipTap/Quill) with content sanitization and markdown support.

- **Development Dashboard (F10)**
  Real-time dashboard showing module status, test coverage, CI health, security/ML/integration scorecards, dependency health.

## Data & ML Platform (Fase 11-13) — Optional Power-up

- **ETL (Extract, Transform, Load)**
  Data pipelines for ingesting, transforming and loading data into storage systems (D02).

- **Dataset Lineage (D03)**
  Tracking of data transformations: which datasets were derived from which sources, enabling reproducibility and compliance.

- **Streaming Data (D04)**
  Real-time data processing via Redis Streams, Kafka or Kinesis adapters.

- **Data Version Control (D05)**
  Git-like versioning for datasets and data artifacts.

- **Structured Output Validation (D06)**
  Validation of JSON/Pydantic models for data quality and ML outputs.

- **Tool-Call Logging (D07)**
  Logging infrastructure for AI agent tool calls with redaction and audit trail.

- **Prompt Experiments (D08)**
  Tracking of prompt variations, parameters and results for iterative improvement.

- **Evaluation & Metrics (D09)**
  Framework for ML model and agent evaluation with custom metrics.

- **Annotation & Labeling (D10)**
  Tools for data annotation and labeling for ML training datasets.

- **Feature Engineering (D11)**
  Reusable feature transformations and patterns for ML pipelines.

- **Model Registry (D12)**
  Registry for ML models with versioning, stage transitions (dev/staging/prod) and metadata.

- **Prompt Template Library (D13)**
  Library of reusable prompt templates with versioning and variable substitution.

- **Agent Operations (D14)**
  Control plane for AI agents: runs, tool calls, policies, rate limiting.

- **Vector Search / RAG (D15)**
  Adapter for vector embeddings and similarity search (pgvector, Pinecone) enabling Retrieval-Augmented Generation patterns.

- **Model Monitoring (D16)**
  Production monitoring for ML models: quality drift, feedback collection, retraining triggers.

---

## Quality & Integration (Fase 14-16) — Lightweight

- **Constitutional Gate (P01)**
  Validates that all modules comply with constitution rules (test coverage, security, accessibility, performance).

- **Security Audit (P02)**
  OWASP ASVS top 20 critical checks for security compliance.

- **ML Governance (P03)**
  Governance checks for ML/AI: evaluation gates, prompt versioning, tool-call redaction.

- **Integration Security (P04)**
  Security checks for integrations: webhook signatures, credential rotation, connector permissions.

- **Dependency Validation (P05)**
  Validates tech stack remains up-to-date and secure: CVEs, deprecations, version constraints.

- **Connector Framework (I01)**
  Manifest-based framework for third-party connectors with SDK patterns.

- **Compliance Exports (I02)**
  Templates for audit bundles and GDPR data exports.

- **Resilience Testing (O01)**
  Validates retry logic, circuit breakers and graceful degradation patterns.
