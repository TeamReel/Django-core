# Composition Patterns

This package is designed for flexible composition. Here are common patterns for building complex UIs.

## Pattern 1: Resource Dashboard Card

Combine HealthStatus, ResourceUsageBar, and Badge in a ResourceCard for a comprehensive resource display.

**Use Case:** Service dashboards, API usage tracking, system monitoring

```tsx
<ResourceCard>
  <ResourceCard.Header>
    <HealthStatus name="API Service" status="healthy" size="small" />
    <Badge variant="success">OK</Badge>
  </ResourceCard.Header>

  <ResourceCard.Body>
    <ResourceUsageBar
      value={750}
      max={1000}
      label="API Calls (Today)"
      unit="calls"
    />
    <ResourceUsageBar
      value={250}
      max={1000}
      label="Remaining"
      unit="calls"
    />
  </ResourceCard.Body>

  <ResourceCard.Footer>
    <button>View Usage Details</button>
  </ResourceCard.Footer>
</ResourceCard>
```

**Key Benefits:**
- Semantic HTML structure
- Self-contained resource display
- Easy to scan visually
- Accessible card layout

**Key Benefits:**

- "View all" button for hidden alerts

## Pattern 4: Inline Alerts with Resource Usage

Combine alerts and usage bars for contextual warnings that appear when thresholds are crossed.

**Use Case:** Credit warnings, quota notifications, usage alerts

```tsx
function ResourceWithAlert({ value, max }: { value: number; max: number }) {
  const percentage = (value / max) * 100;
  const isHighUsage = percentage >= 85;

  return (
    <div>
      <ResourceUsageBar
        value={value}
        max={max}
        label="API Credits"
        unit="credits"
      />

      {isHighUsage && (
        <Alert
          title="Credit Usage High"
          severity="warning"
          style={{ marginTop: '8px' }}
        >
          You're at {percentage.toFixed(0)}% of your credit limit. Consider upgrading.
        </Alert>
      )}
    </div>
  );
}

// Usage
<ResourceWithAlert value={950} max={1000} />
```

**Key Benefits:**
- Contextual alerts appear only when needed
- Visual connection between metric and alert
- Reduces alert fatigue
- Clear call-to-action

## Pattern 8: Dynamic Severity Calculation

Automatically adjust alert severity based on resource usage levels.

**Use Case:** Adaptive warnings, threshold-based alerts, progressive notifications

```tsx
function DynamicResourceAlert({ value, max }: { value: number; max: number }) {
  const percentage = (value / max) * 100;

  let severity: 'info' | 'warning' | 'error' = 'info';
  let title = 'Resource Usage';
  let message = `You're using ${value} of ${max}.`;

  if (percentage >= 95) {
    severity = 'error';
    title = 'Critical: Resource Limit Reached';
    message = `You're at ${percentage.toFixed(0)}% capacity. Immediate action required.`;
  } else if (percentage >= 85) {
    severity = 'warning';
    title = 'Warning: High Resource Usage';
    message = `You're at ${percentage.toFixed(0)}% capacity. Consider upgrading soon.`;
  }

  return (
    <>
      <ResourceUsageBar value={value} max={max} label="Usage" />
      {percentage >= 85 && (
        <Alert title={title} severity={severity}>
          {message}
        </Alert>
      )}
    </>
  );
}
```

**Key Benefits:**
- Progressive warnings
- Prevents alert fatigue
- Clear escalation path
- User-friendly thresholds

## Tips for Composition

1. **ResourceCard works with any children** - Don't limit yourself to F05 components. Any React component can go inside.

2. **AlertStack automatically spaces alerts** - Use F01 design tokens for consistent spacing. No custom CSS needed.

3. **Compound components provide flexible layout** - ResourceCard.Header/Body/Footer can be used in any order or omitted entirely.

4. **Use semantic HTML** - All components use proper semantic elements (`<header>`, `<main>`, `<footer>`, `<article>`, etc.).

5. **Combine with F01 design system** - All components are designed to work seamlessly with F01's color tokens, spacing, and typography.

6. **Think in terms of user tasks** - Group related information together (e.g., health status + usage bar + actions).

7. **Progressive disclosure** - Start with summary views (badges, status), provide details on interaction (tooltips, modals).

8. **Responsive by default** - All components adapt to container width. Use CSS Grid/Flexbox for layouts.

## Accessibility Considerations

All composition patterns maintain WCAG 2.1 AA compliance:

- **Keyboard navigation**: Tab through all interactive elements
- **Screen reader support**: Proper ARIA labels and roles
- **Color contrast**: All text meets 4.5:1 ratio
- **Focus management**: Visible focus indicators
- **Motion sensitivity**: Animations respect `prefers-reduced-motion`

## Performance Tips

- **Tree-shaking**: Import only components you use
- **Lazy loading**: Use React.lazy() for less-common components
- **Memoization**: Wrap expensive compositions in React.memo()
- **Avoid deep nesting**: Keep component trees shallow for better performance
